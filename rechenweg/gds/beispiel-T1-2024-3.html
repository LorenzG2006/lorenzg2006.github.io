Überblick

(a) Definitionen der VO der Reihe nach prüfen: Blockcode (alle Wörter gleich lang), linear (Summe modulo 2 zweier Codewörter ist wieder Codewort), zyklisch (linear und jede Rotation eines Codeworts ist wieder Codewort); DDD = kleinste Distanz zweier verschiedener Codewörter. (b), (c) Informationsgehalt h=ld⁡(1/p)h = \operatorname{ld}(1/p)h=ld(1/p), Entropie als gewichtetes Mittel, Redundanz R=L−HR = L - HR=L−H. (d) Polynomcode (CRC): Nachricht um r=grad⁡Gr = \operatorname{grad} Gr=gradG Nullen verlängern, durch GGG teilen (modulo 2), Rest anhängen.

(a) Codearten und Hamming-Distanz

Code {0110,0000,1001,1111}\{0110, 0000, 1001, 1111\}{0110,0000,1001,1111}

  • Blockcode: alle Wörter haben Länge 4 → ja.
  • Linear: Alle Summen (bitweises XOR) prüfen. Mit 000000000000 ist jede Summe trivial (c⊕0000=cc \oplus 0000 = cc⊕0000=c, c⊕c=0000c \oplus c = 0000c⊕c=0000). Die übrigen: 0110⊕1001=11110110 \oplus 1001 = 11110110⊕1001=1111 ✓, 0110⊕1111=10010110 \oplus 1111 = 10010110⊕1111=1001 ✓, 1001⊕1111=01101001 \oplus 1111 = 01101001⊕1111=0110 ✓ → ja.
  • Zyklisch: Rotation von 011001100110 um eine Stelle nach links ergibt 110011001100 – kein Codewort → nein.
  • Distanzen: d(0110,0000)=2d(0110, 0000) = 2d(0110,0000)=2, d(0110,1001)=4d(0110, 1001) = 4d(0110,1001)=4, d(0110,1111)=2d(0110, 1111) = 2d(0110,1111)=2, d(0000,1001)=2d(0000, 1001) = 2d(0000,1001)=2, d(0000,1111)=4d(0000, 1111) = 4d(0000,1111)=4, d(1001,1111)=2d(1001, 1111) = 2d(1001,1111)=2. Minimum: D=2D = 2D=2.

Code {1000,0100,0010,0001}\{1000, 0100, 0010, 0001\}{1000,0100,0010,0001}

  • Blockcode: ja (Länge 4).
  • Linear: 1000⊕0100=11001000 \oplus 0100 = 11001000⊕0100=1100 ist kein Codewort (außerdem fehlt 000000000000, das in jedem linearen Code liegt, da c⊕c=0000c \oplus c = 0000c⊕c=0000) → nein.
  • Zyklisch: Zwar ergibt jede Rotation wieder ein Codewort, aber ein zyklischer Code ist laut Definition ein linearer Code mit dieser Eigenschaft → nein.
  • Distanzen: Je zwei Wörter unterscheiden sich an genau 2 Stellen (dort, wo jeweils die Eins steht) → D=2D = 2D=2.

Code {000,111}\{000, 111\}{000,111}

  • Blockcode: ja.
  • Linear: 000⊕111=111000 \oplus 111 = 111000⊕111=111, 111⊕111=000111 \oplus 111 = 000111⊕111=000, 000⊕000=000000 \oplus 000 = 000000⊕000=000 → ja.
  • Zyklisch: Rotationen von 000000000 bzw. 111111111 ergeben wieder 000000000 bzw. 111111111 → ja.
  • Distanz: d(000,111)=3d(000, 111) = 3d(000,111)=3 → D=3D = 3D=3.

(c) Artikelnummern

Eine Artikelnummer hat die Form Kategorie – Hex Hex Hex, z. B. „H–0A3“.

(i) Informationsgehalt

Bindestrich: Er steht in jeder Artikelnummer an derselben Stelle, tritt also mit Wahrscheinlichkeit p=1p = 1p=1 auf:

h(–)=ld⁡11=0 Bit.h(\text{–}) = \operatorname{ld}\frac{1}{1} = 0 \text{ Bit}.h(–)=ld11​=0 Bit.

Er trägt keine Information (der Empfänger weiß vorher, dass er kommt).

Ganze Artikelnummer: Anzahl der möglichen Nummern: 444 Kategorien mal 16316^3163 Hex-Zahlen:

N=4⋅163=22⋅212=214=16384.N = 4 \cdot 16^3 = 2^2 \cdot 2^{12} = 2^{14} = 16384.N=4⋅163=22⋅212=214=16384.

Alle gleich wahrscheinlich, also p=2−14p = 2^{-14}p=2−14 und

h=ld⁡1p=ld⁡214=14 Bit.h = \operatorname{ld}\frac{1}{p} = \operatorname{ld} 2^{14} = 14 \text{ Bit}.h=ldp1​=ld214=14 Bit.

(Probe über Additivität: Kategorie ld⁡4=2\operatorname{ld} 4 = 2ld4=2 Bit, jede Hex-Ziffer ld⁡16=4\operatorname{ld} 16 = 4ld16=4 Bit, Bindestrich 000 Bit: 2+0+3⋅4=142 + 0 + 3 \cdot 4 = 142+0+3⋅4=14 Bit.)

(ii) Redundanz mit zwei Prüfziffern zur Basis 8

Eine optimale binäre Codierung einer Artikelnummer braucht genau 141414 Bit (2 Bit Kategorie, 12 Bit für die drei Hex-Ziffern, der Bindestrich wird nicht übertragen). Jede Oktalziffer braucht ld⁡8=3\operatorname{ld} 8 = 3ld8=3 Bit, zwei Prüfziffern also 666 Bit. Damit:

L=14+6=20 Bit,H=14 Bit,R=L−H=6 Bit.L = 14 + 6 = 20 \text{ Bit}, \qquad H = 14 \text{ Bit}, \qquad R = L - H = 6 \text{ Bit}.L=14+6=20 Bit,H=14 Bit,R=L−H=6 Bit.

Teil (c)

(i) h(–)=0h(\text{–}) = 0h(–)=0 Bit; h(Artikelnummer)=14h(\text{Artikelnummer}) = 14h(Artikelnummer)=14 Bit.
(ii) R=20−14=6R = 20 - 14 = 6R=20−14=6 Bit (relative Redundanz r=6/20=0.3r = 6/20 = 0.3r=6/20=0.3).

Annahme

Wir nehmen an, dass die Artikelnummer selbst redundanzfrei codiert wird (14 Bit). Würde man z. B. den Bindestrich mitcodieren, käme dessen Codelänge zur Redundanz dazu – die Prüfziffern allein verursachen in jedem Fall 666 Bit Redundanz.

Hilfreiches

Arten von Binärcodes (VO)

Blockcode: konstante Codewortlänge. Linearer Code: Blockcode, in dem für alle Codewörter c1,c2c_1, c_2c1​,c2​ auch c1+c2c_1 + c_2c1​+c2​ (bitweise modulo 2) ein Codewort ist. Zyklischer Code: linearer Code, in dem mit (a0a1⋯an−1)(a_0 a_1 \cdots a_{n-1})(a0​a1​⋯an−1​) auch (a1⋯an−1a0)(a_1 \cdots a_{n-1} a_0)(a1​⋯an−1​a0​) ein Codewort ist. Hamming-Distanz DDD des Codes: minimaler Abstand zweier verschiedener Codewörter.

Informationsgehalt und Redundanz

h=ld⁡(1/p)h = \operatorname{ld}(1/p)h=ld(1/p) Bit; bei NNN gleich wahrscheinlichen Möglichkeiten h=ld⁡Nh = \operatorname{ld} Nh=ldN. R=L−HR = L - HR=L−H (Bit), r=R/Lr = R/Lr=R/L.

Polynomcode (CRC)
  1. M(x)M(x)M(x) aus den Datenbits; r=grad⁡Gr = \operatorname{grad} Gr=gradG.
  2. xrM(x)x^r M(x)xrM(x) bilden (rrr Nullen anhängen).
  3. Durch G(x)G(x)G(x) modulo 2 dividieren → Rest R(x)R(x)R(x) mit grad⁡R<r\operatorname{grad} R < rgradR<r.
  4. T(x)=xrM(x)+R(x)T(x) = x^r M(x) + R(x)T(x)=xrM(x)+R(x) senden. Der Empfänger teilt durch GGG; Rest ≠0\ne 0=0 ⇒ Fehler erkannt.

(Polynomcodes kamen in den Tests 2022W–2024W vor; in den aktuellen Folien werden sie nur kurz als Beispiel zyklischer Codes erwähnt.)

Typische Fehler
  • Zyklisch ankreuzen, obwohl der Code nicht linear ist.
  • Den Bindestrich mit h=ld⁡1/(Anzahl Zeichen)h = \operatorname{ld} 1/(\text{Anzahl Zeichen})h=ld1/(Anzahl Zeichen) bewerten – er ist sicher, also 000 Bit.
  • Bei der CRC vergessen, vor der Division rrr Nullen anzuhängen.
  • Bei der Division normal subtrahieren statt XOR.
