Angabe Originalseite

Folgende Bitmuster sind gegeben: Z1=11001001Z_1 = 11001001Z1​=11001001 und Z2=00011101Z_2 = 00011101Z2​=00011101.

Je nach verwendeter Zahlendarstellung repräsentieren diese Bitmuster unterschiedliche Zahlen. In den Unterpunkten a) bis c) ist jeweils ein aus der Vorlesung bekanntes Zahlendarstellungsformat gegeben. Interpretieren Sie Z1Z_1Z1​ und Z2Z_2Z2​ als Zahlendarstellung in dem jeweiligen Format und führen Sie damit die Berechnung

−(Z1+Z2)-(Z_1 + Z_2)−(Z1​+Z2​)

(Addition von Z1Z_1Z1​ und Z2Z_2Z2​ mit anschließender arithmetischer Negation des Ergebnisses) mit einer Maschinenwortlänge von 8 Bit in dem gegebenen Format durch. Geben Sie Zwischenschritte an. Geben Sie das Ergebnis der Berechnung im gegebenen Format und auch als decodierte Dezimalzahl an.

b) Zweierkomplementdarstellung

Überblick

Dasselbe Bitmuster bedeutet je nach Format eine andere Zahl. In jedem Teil gehen wir gleich vor:

  1. Z1Z_1Z1​, Z2Z_2Z2​ im Format decodieren (zur Orientierung und zur Kontrolle).
  2. Addition im Format – mit den Regeln des Formats (Fallunterscheidung bei Vorzeichen/Betrag, normale Addition mod 282^828 beim Zweierkomplement, Exzess-Korrektur bei Exzess).
  3. Negation im Format (Vorzeichenbit kippen / invertieren und +1+1+1 / 0e−Xe+e0_e - X_e + e0e​−Xe​+e).
  4. Ergebnis als Bitmuster und dezimal angeben.

a) Vorzeichen und Betrag

Decodieren: erstes Bit = Vorzeichen, Rest = Betrag (7 Bit).

  • Z1=1 1001001Z_1 = 1\,1001001Z1​=11001001: Vorzeichen −-−, Betrag (1001001)2=64+8+1=73(1001001)_2 = 64 + 8 + 1 = 73(1001001)2​=64+8+1=73 → Z1=−73Z_1 = -73Z1​=−73.
  • Z2=0 0011101Z_2 = 0\,0011101Z2​=00011101: Vorzeichen +++, Betrag (0011101)2=16+8+4+1=29(0011101)_2 = 16 + 8 + 4 + 1 = 29(0011101)2​=16+8+4+1=29 → Z2=+29Z_2 = +29Z2​=+29.

Addition: Die Vorzeichen sind verschieden. Dann darf man die Bitmuster nicht einfach addieren, sondern muss den kleineren Betrag vom größeren subtrahieren; das Ergebnis erhält das Vorzeichen der betragsmäßig größeren Zahl. Vergleich der Beträge: 1001001>00111011001001 > 00111011001001>0011101 (erste Stelle von links, an der sie sich unterscheiden: 111 gegen 000). Also:

       1 0 0 1 0 0 1      |Z1|
   -   0 0 1 1 1 0 1      |Z2|
  Ü    1 1 1 1 0 0 0      (geborgt)
  -------------------
   =   0 1 0 1 1 0 0

Betrag der Summe (0101100)2(0101100)_2(0101100)2​, Vorzeichen von Z1Z_1Z1​ (negativ):

Z1+Z2=1 0101100(=−44).Z_1 + Z_2 = 1\,0101100 \quad (= -44).Z1​+Z2​=10101100(=−44).

Negation: Bei Vorzeichen/Betrag wird nur das Vorzeichenbit gekippt:

−(Z1+Z2)=0 0101100.-(Z_1 + Z_2) = 0\,0101100.−(Z1​+Z2​)=00101100.

Decodieren: +(0101100)2=32+8+4=44+(0101100)_2 = 32 + 8 + 4 = 44+(0101100)2​=32+8+4=44.

b) Zweierkomplement

Decodieren: Das erste Bit hat das Gewicht −27=−128-2^7 = -128−27=−128.

  • Z1=11001001Z_1 = 11001001Z1​=11001001: negativ. Betrag durch Invertieren und +1+1+1: 00110110+1=00110111=32+16+4+2+1=5500110110 + 1 = 00110111 = 32+16+4+2+1 = 5500110110+1=00110111=32+16+4+2+1=55 → Z1=−55Z_1 = -55Z1​=−55. (Oder: −128+64+8+1=−55-128 + 64 + 8 + 1 = -55−128+64+8+1=−55.)
  • Z2=00011101=29Z_2 = 00011101 = 29Z2​=00011101=29 (positiv, wie oben).

Addition: Im Zweierkomplement wird ohne Fallunterscheidung ganz normal binär addiert; ein Übertrag aus dem 8. Bit würde ignoriert.

       1 1 0 0 1 0 0 1      Z1
   +   0 0 0 1 1 1 0 1      Z2
  Ü    0 0 1 1 0 0 1 0
  ---------------------
   =   1 1 1 0 0 1 1 0

Kein Übertrag aus dem höchsten Bit, und da die Summanden verschiedene Vorzeichen haben, kann ohnehin kein Überlauf entstehen. Z1+Z2=11100110Z_1 + Z_2 = 11100110Z1​+Z2​=11100110 (=−128+64+32+4+2=−26= -128 + 64 + 32 + 4 + 2 = -26=−128+64+32+4+2=−26).

(Die letzte Stelle ist 1+1=(10)21 + 1 = (10)_21+1=(10)2​, der Übertrag geht in die vorletzte Stelle: 0+1=10 + 1 = 10+1=1.)

Hilfreiches

Addition und Negation je Format
  • Vorzeichen/Betrag: gleiche Vorzeichen → Beträge addieren, Vorzeichen behalten; verschiedene → kleineren Betrag vom größeren abziehen, Vorzeichen des größeren. Negation: Vorzeichenbit kippen.
  • Zweierkomplement: einfach addieren, Übertrag aus dem höchsten Bit verwerfen. Negation: invertieren, +1+1+1. Überlauf nur bei gleichen Vorzeichen der Summanden und anderem Vorzeichen des Ergebnisses.
  • Exzess eee: (A+B)e=Ae+Be−e(A+B)_e = A_e + B_e - e(A+B)e​=Ae​+Be​−e, (A−B)e=Ae−Be+e(A-B)_e = A_e - B_e + e(A−B)e​=Ae​−Be​+e, (−A)e=0e−Ae+e(-A)_e = 0_e - A_e + e(−A)e​=0e​−Ae​+e mit 0e=e0_e = e0e​=e.
Typische Fehler
  • Bei Vorzeichen/Betrag die Bitmuster „naiv“ addieren: 11001001+00011101=1110011011001001 + 00011101 = 1110011011001001+00011101=11100110 wäre hier −102-102−102 – falsch.
  • Beim Zweierkomplement nur invertieren (das wäre Einerkomplement) und das +1+1+1 vergessen.
  • Bei Exzess den doppelten Exzess nach der Addition nicht korrigieren, oder bei der Negation einfach invertieren.
  • Das Ergebnis nicht decodieren – verlangt ist Bitmuster und Dezimalzahl.
