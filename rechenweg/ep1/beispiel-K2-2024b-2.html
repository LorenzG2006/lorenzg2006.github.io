Angabe Originalseite

Einstufungstest K2, WS2024 (Beispieltest 2), Methode 2 von 4 – (6 Punkte)

Einschränkungen

  • Sie dürfen keine zusätzlichen eigenen Hilfsmethoden oder Klassenvariablen verwenden.
  • Die vorgegebenen Methodenköpfe dürfen nicht erweitert oder geändert werden.
  • Sie dürfen Strings nicht per Referenz vergleichen.
  • Sie dürfen nicht die Klassen StringBuffer bzw. StringBuilder verwenden.
  • Sie dürfen keine Lambdas, Streams oder Methodenreferenzen verwenden.
  • Sie dürfen nur folgende Methode(n) aus der Klasse String verwenden: charAt, equals, length, substring.
  • Sonst darf keine weitere Klasse verwendet werden.

Aufgabenstellung

String getThird(String a, String b, String c) vergleicht den Inhalt der Parameter a, b und c und gibt davon abhängig einen String zurück. Sind alle drei Parameter gleich, ist der Rückgabewert "alle gleich". Sind alle drei Parameter unterschiedlich, ist der Rückgabewert "alle unterschiedlich". Sind genau zwei Parameter gleich, wird der dritte (zu den anderen unterschiedliche) zurückgegeben. Annahme(n): a != null, b != null, c != null.

Aufruf Ausgabe in main auf der Konsole
getThird("toss", "a", "coin") alle unterschiedlich
getThird("Blaukraut", "bleibt", test) bleibt
getThird("badger", "badger", "badger") alle gleich

(test = "Blaukraut".)

Bewertung: korrekter Vergleich 2, korrekte Verzweigungen 2, korrekte Rückgabe 2.

Lösung

Lösung verborgen – erst selbst probieren!

Überblick

Bei drei Strings gibt es genau fünf Muster: alle gleich; a=b≠ca = b \ne ca=b=c; a=c≠ba = c \ne ba=c=b; b=c≠ab = c \ne ab=c=a; alle verschieden. Wir prüfen sie in einer if-Kette von oben nach unten. Der Inhalt wird mit equals verglichen – == würde nur prüfen, ob es dasselbe Objekt ist, und ist laut Angabe verboten.

Code

public static String getThird(String a, String b, String c) {
    if (a.equals(b) && b.equals(c)) {
        return "alle gleich";
    }
    if (a.equals(b)) {
        return c;
    }
    if (a.equals(c)) {
        return b;
    }
    if (b.equals(c)) {
        return a;
    }
    return "alle unterschiedlich";
}

Schritt für Schritt

  1. Alle gleich zuerst: a.equals(b) && b.equals(c) (Gleichheit ist transitiv, damit ist auch a=ca = ca=c). Diese Prüfung muss vor den Zweier-Fällen stehen, sonst würde z. B. bei "badger"×3 schon a.equals(b) greifen und c zurückgegeben.
  2. Genau zwei gleich: Wenn wir hier ankommen, sind nicht alle drei gleich. Ist also a.equals(b), so muss c verschieden sein → return c;. Analog a.equals(c) → b, b.equals(c) → a.
  3. Sonst sind alle paarweise verschieden → "alle unterschiedlich".

Trace für getThird("Blaukraut", "bleibt", test) mit test = "Blaukraut"

Prüfung Ergebnis
a.equals(b) && b.equals(c) "Blaukraut".equals("bleibt") = false → weiter
a.equals(b) false → weiter
a.equals(c) "Blaukraut".equals("Blaukraut") = true → return b

Rückgabe bleibt ✓. Bei ("toss", "a", "coin") sind alle vier Prüfungen falsch → alle unterschiedlich ✓.

Kompiliert und getestet (javac/java, JDK 21)

Ausgabe der Beispielaufrufe (identisch mit der Angabe):

alle unterschiedlich
bleibt
alle gleich

Eigene Randfälle (alle Positionen des „Dritten“ und ein Inhalts- statt Referenzvergleich):

getThird("x", "y", "y")              = x
getThird("y", "x", "y")              = x
getThird("", "", "z")                = z
getThird(new String("q"), "q", "q")  = alle gleich   (verschiedene Objekte, gleicher Inhalt)
Ergebnis

if-Kette: zuerst „alle gleich“, dann die drei Paare (a,b → c; a,c → b; b,c → a), sonst „alle unterschiedlich“; Vergleich immer mit equals (Code oben).

Hilfreiches

equals vs. ==

s.equals(t) vergleicht den Inhalt zweier Strings. s == t vergleicht die Referenzen (dasselbe Objekt?) und kann bei gleichem Inhalt false liefern, z. B. bei new String("q") == "q".

Typische Fehler
  • == statt equals – laut Angabe verboten und bei zur Laufzeit erzeugten Strings falsch.
  • Zweier-Fälle vor dem „alle gleich“-Fall prüfen.
  • Falschen String zurückgeben (bei a=ba = ba=b den Wert a statt des abweichenden c).
  • Strings "alle gleich" / "alle unterschiedlich" mit Tippfehler – die Ausgabe muss exakt stimmen.
