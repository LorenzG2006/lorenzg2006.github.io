Aufgabenstellung

int sumUp(int d, int s, int t) erhöht s, bis s nicht mehr kleiner als t ist. Dazu wird wiederholt der Rest der Division s/d zu s addiert. Ist der Rest 0, dann wird statt dessen 1 addiert. Gibt zurück, wie oft der Rest der Division 0 war. Annahme(n): 0 < d, 0 < s < t.

Aufruf Ausgabe in main auf der Konsole
sumUp(2, 5, 11) 3
sumUp(8, 8, 40) 4
sumUp(5, 1, 2000) 0

Bewertung: korrekte Schleife(n) 1, korrekter Test 1, korrekte Berechnung und Rückgabe 3.

Lösung

Lösung verborgen – erst selbst probieren!

Überblick

Wie oft die Schleife läuft, steht nicht vorher fest – sie läuft, solange s < t gilt. Das ist der typische Fall für eine while-Schleife. In jedem Durchlauf berechnen wir rest = s % d; ist er 0, addieren wir 1 und zählen mit, sonst addieren wir den Rest. Die Schleife endet sicher, weil s in jedem Durchlauf um mindestens 1 wächst.

Code

public static int sumUp(int d, int s, int t) {
    int zeros = 0;
    while (s < t) {
        int rest = s % d;
        if (rest == 0) {
            s += 1;
            zeros++;
        } else {
            s += rest;
        }
    }
    return zeros;
}

Schritt für Schritt

  1. Zähler zeros = 0 für die Nullreste.
  2. Schleifenbedingung s < t – „erhöhen, bis s nicht mehr kleiner als t ist“ heißt: weitermachen, solange s < t.
  3. Rest berechnen mit s % d (Annahme d > 0, also keine Division durch 0).
  4. Fallunterscheidung: Rest 0 → s += 1 und zeros++; sonst s += rest. Der Parameter s darf verändert werden – er ist eine lokale Kopie, der Aufrufer merkt davon nichts.
  5. Rückgabe der Anzahl Nullreste.

Warum liefert sumUp(5, 1, 2000) genau 0?

Addiert man zu sss seinen Rest r=s mod dr = s \bmod dr=smodd, so gilt s+r≡2s(modd)s + r \equiv 2s \pmod ds+r≡2s(modd). Der Rest verdoppelt sich also in jedem Schritt modulo 5: 1→2→4→3→1→…1 \to 2 \to 4 \to 3 \to 1 \to \dots1→2→4→3→1→… Da 2s≡0(mod5)2s \equiv 0 \pmod 52s≡0(mod5) nur für s≡0s \equiv 0s≡0 gilt, wird der Rest nie 0, wenn er nicht schon 0 war. Bei Start s=1s = 1s=1 ist das Ergebnis daher 0 – die Schleife läuft trotzdem, bis s≥2000s \ge 2000s≥2000.

Ergebnis

while (s < t): Rest s % d; bei 0 s += 1 und Nullreste zählen, sonst s += rest; nach der Schleife den Zähler zurückgeben (Code oben).

Hilfreiches

while-Schleife

while (bedingung) { … } prüft die Bedingung vor jedem Durchlauf und läuft, solange sie wahr ist. Geeignet, wenn die Anzahl der Durchläufe vorher unbekannt ist. Die Schleife muss die Bedingung irgendwann falsch machen (hier: s wächst immer).

Typische Fehler
  • while (s <= t) – dann läuft die Schleife bei s == t noch einmal (Off-by-one; sumUp(8, 8, 40) liefert dann 5 statt 4, weil bei s = 40 noch ein Nullrest gezählt wird).
  • Bei Rest 0 gar nichts addieren → Endlosschleife.
  • Die Summe statt der Anzahl Nullreste zurückgeben.
  • rest außerhalb der Schleife einmal berechnen und nie aktualisieren.

Verwandte Beispiele: K2-2024c.2 (addMark), K2-2024c.5 (main mit short-Überlauf), K2-2024.1 (countDivisors).
